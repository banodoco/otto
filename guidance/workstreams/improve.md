# Improve workspace guidance

## When to use

No generic rule yet.

## Outcome

No generic rule yet.

## Inputs

The recorded failure or need, one authoritative source, neighboring references, existing tests and permission to change the machinery.

## Procedure

Identify the owning source, make the smallest coherent change, run the relevant checks and record the fix without duplicating policy.

Words follow the [glossary](../glossary.md).

## Completion

Documentation and generated views remain consistent, original regressions are covered and the change's proof is recorded.

## Scope

1. Start from a recorded failure: a process ledger entry, an issue or an accepted card. No failure, no change.

2. Find the rule's one authoritative home (see the [run contract](../run-contract.md) and [author guidance](../stand-up.md#author-guidance)). Change it and nothing else; replace any copy with a link to the home's heading.

3. If you add words, cut as many.

## Evidence and handoff

Run an audit when a process ledger entry from a run names friction in the skills, or the owner asks; never on a schedule. `N` helpers each map one area read-only: a skill, a guide, the templates. One high-judgment critic then verifies their claims against the code and judges them. The output is ledger entries and at most one proposal, not edits.
