A draft can use a short outline with unknowns. Before dispatch, name each task's bounded outcome, inputs and deliverable, dependencies, suitable route and focused proof. Reuse source identities in inputs instead of repeating them.

**Task ids:** Use stable, unique task IDs, for example AB-1 and AB-2.

**Critical path:** List the ordered task IDs that bound the finish.

**Test inventory:** Name the existing checks or tests affected, if any.

Add task details below the table only when useful. Scope names the surfaces and contracts a task may change, including their tests. Identify dependencies where tasks would change the same surface. A proof names the observable behavior and its inputs; do not invent broad checks, duplicate task ledgers or extra approvals. Record actual review work and findings in task rows when applicable.
